# AGENTS.md — avivashishta.com

Instructions for AI coding agents working in this repository. Public repo:
https://github.com/AVIVASHISHTA29/repository-2024

## What this is

The source of https://www.avivashishta.com — a personal portfolio built as a
React 19 + TypeScript single-page app with Vite, deployed on Vercel. It is
notable for real-time hand-gesture and head-tracking navigation (MediaPipe), a
Three.js / React Three Fiber 3D scene, GSAP scroll animation, and an in-page
terminal (`Ctrl + J`) with 27 commands and AI chat.

## Layout

| Path | What lives there |
| --- | --- |
| `src/` | The React app. `src/pages/Home.tsx` is the only page — **there is no client-side router**. |
| `src/components/` | UI, grouped by area (`Terminal/`, `WindowManager/`, `Shared/`). |
| `src/store/` | Zustand stores. Several components manage their own visibility through these rather than through props. |
| `src/hooks/`, `src/providers/` | Gesture/camera input plumbing. |
| `api/` | Vercel serverless functions. `_content.js` is a shared module, not a route (leading underscore). |
| `middleware.ts` | Vercel Edge Middleware — markdown content negotiation. Runs *before* the filesystem. |
| `public/` | Static assets, hand-written blog HTML, and generated pages. |
| `scripts/` | Build and verification scripts. |

## Commands

```bash
npm run dev              # Vite dev server
npm run build            # build:pages -> tsc -> vite build
npm run build:pages      # regenerate static pages from api/_content.js
npm run verify:agentic   # assert the agent-readiness contract against a live URL
```

`tsc` only type-checks `src` (see `tsconfig.json` `include`). Files under `api/`
and `middleware.ts` are compiled by Vercel, so a type error there will not
surface locally — be careful when editing them.

## Rules to follow

**Do not hand-edit the generated pages.** `public/about/index.html`,
`public/contact/index.html`, `public/privacy/index.html` and
`public/developers/index.html` are generated by `scripts/build-pages.mjs` from
the markdown in `api/_content.js`, as is the `<!-- BEGIN:static-content -->`
block in `index.html`. Edit the markdown and re-run `npm run build:pages`;
anything written directly into those files is overwritten on the next build.

**Keep the single source single.** The same markdown in `api/_content.js` backs
the HTML pages, the `Accept: text/markdown` responses and the 404 body. That is
deliberate — it is what stops the three from drifting.

**Do not reintroduce an SPA catch-all rewrite.** The app has no router, so
unmatched paths must reach `api/notfound.ts` and return a real HTTP 404.
Serving the app shell with a 200 for every path is the bug that
`vercel.json`'s `framework: null` plus the `/((?!api/).*)` rewrite exists to
prevent.

**Content negotiation belongs in `middleware.ts`, not `vercel.json`.** Vercel
resolves the filesystem before applying rewrites, so a `has: accept` rewrite
never fires for a path that has a static file. Middleware runs earlier.

**Preserve the visual design.** The prerendered homepage content in
`index.html` is hidden by an inline script the moment JS runs; it exists for
crawlers and no-JS clients only. Do not make it visible to normal visitors.

**Verify after changing anything public-facing.** Run
`npm run verify:agentic -- <deployment-url>` — it checks 404 behaviour, no-JS
content, markdown negotiation, `Vary` headers, trust-anchor pages, JSON-LD
completeness and robots policy.

## Style

Match the surrounding code: functional components with hooks, Zustand for shared
state, SCSS modules under `src/styles/`. TypeScript is strict. Comments are
sparse — write one only where the reason for the code is not obvious from the
code.

## Secrets

`api/chat.ts` needs `OPENAI_API_KEY` in the Vercel environment. Never commit a
key or add one to a client-side file — anything under `src/` ships to the
browser.
